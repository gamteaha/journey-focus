# 캐릭터로 탑승하고 자리를 고르는 객실

2026-11-04 사용자 요구: 캐릭터는 주인공이다. 사용자가 객실 안에서 이동해 원하는 자리에 앉고, 객실/창밖 화면을 전환한다. 최종 목표는 친구들도 같은 열차에 들어와 함께 앉고 같은 여정을 진행하는 것이다.

최신 출발 후 구도와 머리 위 누적 시간 표시는 [캐릭터 공부 화면](study-character-view.md)을 참고한다.

## 이번에 구현한 것

- [승차권 입장](boarding-flow.md)을 마치면 객실로 들어간다. 사용자가 제공한 `assets-source/subway-car/SubwayCar_Compiled.fbx`를 실제로 불러온다. 재질은 로컬 앱에서 다시 지정하며 원본 파일은 수정하지 않았다. 첨부된 외국 포스터/가상 노선도는 현재 표시하지 않는다.
- `public/avatar.mjs`의 임시 파란 캐릭터. 코드로 만든 메시를 사용하며 Meshy 다운로드 결과물이 아니다. 이동 중 다리/팔 동작, 앉는 자세를 적용한다.
- WASD, 방향키, 화면 방향 버튼, 통로 바닥 클릭으로 이동한다. 걷는 범위를 통로로 제한하고 좌석 선택을 확정하면 통로를 따라 접근해 앉는다. E로 후보 좌석에 앉거나 일어난다.
- 실제 모델의 좌석 배치를 기준으로 A/B 각 20개, 총 40개 좌석을 배치했다. 의자를 클릭하면 색으로 미리 보여주고 캐릭터 옆 ‘앉기’ 버튼으로 확정한다. 드롭다운은 제거했다. [전체 화면과 좌석 상호작용](immersive-game.md)에 최신 UI와 검증 범위를 기록했다.
- `객실 · 캐릭터` / `창밖 풍경` 전환. 화면 전환 시 좌석과 타이머를 유지한다. 좌석에 앉아야 새 여정을 시작할 수 있다. 여정 중 일어나거나 다른 자리로 옮겨도 같은 여정은 유지된다.
- A/B 좌석 선택에 따라 지도 창가 방향을 왼쪽/오른쪽으로 변경한다. 창밖 화면의 지도 직접 조작 잠금은 유지한다.
- 객실과 지도는 별도 프레임과 렌더러로 분리했다. 객실은 반대쪽 루프백 호스트(localhost ↔ 127.0.0.1)에서 실행하고 `postMessage`의 source/origin과 좌석 ID를 검증해 상태만 교환한다. 객실 HTML의 frame-ancestors는 같은 포트의 두 루프백 출처로 제한하며 API의 교차 출처 접근 차단은 유지한다.
- 객실 창은 시험용 색 유리이며 실제 노선 풍경은 `창밖 풍경` 화면에서 본다. 객실이 보일 때 지도 SDK의 `targetFrameRate`를 2로 제한하고, 창밖 화면에서는 원래 프레임 설정과 사용자가 고른 품질을 복구한다. 의도적인 2fps 갱신을 자동 성능 저하 판정에서 제외한다.
- 객실 이동과 착석은 지도 API 연결 없이도 작동한다. 창밖 지도와 여정 시작은 기존 VWorld/T Data 연결을 필요로 한다.

## 현재 범위와 한계

- 친구 접속, 초대 링크, 방, 다른 사용자 표시, 서버 좌석 점유 검증은 미구현이다. 가짜 친구나 실제 접속처럼 보이는 인원 수를 표시하지 않는다.
- 객실 창 안의 실시간 지도 합성, 좌석 행별 시차·양쪽 창의 서로 다른 시야·정확한 열차 표고는 미구현이다. 좌석의 A/B 방향만 창밖 화면 카메라에 반영한다.
- FBX 모델을 크기 0.004, Y축 회전 90도, X=-238.399536×0.004 / Y=400×0.004로 보정했다. 실제 차량 치수·국내 차량 종류와의 일치는 미검증이다. 통로 경계 기반 이동이며 모든 손잡이/봉의 정밀 충돌은 구현하지 않았다.
- 캐릭터 원본이 확보되면 `createAvatar()`가 반환하는 `root`와 `pose()` 인터페이스를 유지하는 어댑터로 교체할 수 있다. 실제 걷기/앉기에는 리깅과 애니메이션 또는 별도의 뼈대 제어가 필요하다.
- Three.js 0.170.0 및 FBXLoader 의존성을 `public/vendor/three/`에 고정 보관했다. MIT 라이선스와 소스 주석을 유지하며 런타임 CDN 및 npm 설치는 필요 없다.
- 이전에 새로고침 정지로 기록한 CDP 타임아웃은 진행 중 이탈 확인창에 테스트 도구가 응답하지 않은 문제였다. 확인창을 수락하면 승차권 화면으로 재진입하고, 취소하면 캐릭터 이동이 유지되는 것을 검증했다. [정정과 입장 흐름](boarding-flow.md)을 참고한다.
- 실시간 지도 복사는 현재 제외했다. 브라우저 종료 시 애니메이션을 멈추며, SDK의 종료 핸들러를 우회하거나 교체하는 실험 코드는 최종 구현에 포함하지 않았다.

## 확인 방법

로컬 서버 실행 후 http://localhost:5173 에서 객실로 들어간다. 의자를 클릭해 색을 확인하고 캐릭터 옆 ‘앉기’ 버튼으로 확정한다. [전체 화면과 좌석 상호작용](immersive-game.md)을 참고한다. `npm test`, `npm run check`로 단위 테스트와 문법 검사를 실행한다.

전용 QA Chrome(9223)이 실행 중일 때 `node scripts/cabin-check.mjs`로 3D 좌석 클릭, 키보드 이동, 착석·일어나기·다른 자리 선택, 여정 중 화면 전환, 지도 입력 잠금/렌더 예산 복구, 1366×650·1100×700·390×844 배치를 확인한다. `JF_QA_PORT=9224`로 다른 전용 프로필을 지정할 수 있다. 최신 결과와 캡처는 루트 `tmp/game-qa/`에 저장한다. 단위 테스트는 승차권과 좌석 미리보기 검증을 포함해 59개다.

`node scripts/cabin-check.mjs --reload`는 이탈 확인창 수락 후 승차권을 다시 발급해 객실에 재진입하는 검사까지 실행한다. 실제 사용자의 이탈 확인창 동작은 유지한다.

## 친구 탑승의 다음 단계

서버가 방의 노선·시작 시각·일시정지를 관리하고 좌석 ID와 소유자를 검증해야 한다. 참가자는 같은 방의 시간으로 여정을 계산하고, 캐릭터 위치와 자세를 동기화한다. 현재 로컬 앱에는 이 네트워크 기능을 연결하지 않았다.
