# 승차권에서 시작하는 입장 흐름

첫 화면에서 노선, 집중시간, 캐릭터 색상과 종이 승차권/교통카드를 고른다. 종이 승차권은 절취선을 따라 일자로 그어 자르고, 교통카드는 마우스나 손가락으로 단말기 위로 끌어 놓으면 객실로 들어간다. 키보드와 보조 입력 사용자를 위한 별도 확인 버튼도 제공한다.

확인 뒤에는 [열차 도착 로딩 화면](arrival-loading.md)에서 객실 렌더링과 초기 창밖 지형 준비가 끝날 때까지 기다린다. 준비가 끝나면 자동으로 객실로 넘어간다. 연결 실패/지연은 재시도할 수 있다.

## 동작

- 실제 역과 시간 설정은 표/카드 옆에 표시한다. 종이표에는 선택한 여정을 인쇄해 보여 준다. 입장 후에는 [객실 전체 화면](immersive-game.md)을 표시하며, 역은 위쪽 전광판에서 안내하고 시간은 출발 후 나타난다. 승차권 재발급은 왼쪽 위 설정에서 연다.
- 집중시간은 1분–2시간 사이에서 분 단위로 선택하거나 [∞ 무제한 순환](unlimited-loop.md)을 선택한다. [시·분 계기판과 추천 정거장](time-journey.md)이 실제 도착역을 추천한다. 무제한에서는 43개 역을 반복하며 남은 시간 대신 누적 시간과 완료한 바퀴 수를 표시한다. 앱 시간은 실제 열차 운행시간을 뜻하지 않는다.
- 블루·민트·앰버는 사용자 제공 캐릭터의 색상 변형이다. 승차권 선택이 실제 3D 아바타 재질에 반영된다.
- 입장 전에는 역 메타데이터만 가져오고, VWorld SDK와 객실 모델은 티켓 확인 뒤 로드한다.
- 종이표는 절취선 위/아래 끝에서 시작해 반대쪽까지 90% 이상 한 방향으로 잘라야 한다. 선을 벗어나거나 중간에서 시작하거나 포인터가 취소되면 입장하지 않는다. 가위 표시와 잘린 선을 진행에 맞춰 표시한다.
- 카드는 카드 중심이 단말기 판독 영역에 들어온 상태에서 놓아야 한다. 단말기 밖에 놓거나 터치가 취소되면 원위치로 돌아온다. 단말기를 클릭하는 것만으로는 입장하지 않는다. 성공 시 1회만 입장하며 ‘승차하였습니다’ 확인을 표시한다.
- 효과음은 Web Audio로 합성한 태그음과 가위 소리다. 카드 태그 시 브라우저 음성 합성으로 `ko-KR`의 ‘승차하였습니다’를 요청한다. 한국어 음성 품질과 실제 재생은 설치된 음성/브라우저에 따른다. ‘안내소리’ 버튼으로 음성과 효과음을 함께 끄며 설정을 로컬에 저장한다.
- 성공 시 `navigator.vibrate()`로 짧은 진동을 요청한다. 지원되지 않는 기기에서는 시각적 확인과 음향 동작을 유지한다. 개발 PC에서 실제 촉감은 검증하지 않았다. [Vibration API](https://developer.mozilla.org/en-US/docs/Web/API/Navigator/vibrate), [SpeechSynthesis](https://developer.mozilla.org/en-US/docs/Web/API/SpeechSynthesis).
- 교통카드는 사용자가 제공한 `img-card1.jpg`의 세로 앞면을 사용한다. 원본은 앞·뒷면 합본이며, 사용자가 세로 앞면만 쓰는 것으로 확인했다. 원본을 바꾸지 않고 CSS로 왼쪽 앞면만 표시한다. 실행 이미지 경로는 `/images/inu-transit-card.jpg`다.
- 처음 교통카드를 고를 때와 단말기에 태그할 때 같은 앞면을 표시한다. 노선·시간 컨트롤은 카드 그림 바깥으로 옮겨 선택 기능을 유지하며, 종이 승차권을 선택하면 기존 티켓 안으로 돌아온다. 태그 화면에서도 선택한 여정·시간·캐릭터는 카드 아래 별도로 표시한다. 이미지 자체의 기본 드래그는 막고 기존 포인터/터치 태그 동작을 유지한다.
- 크기 기준: 세로 교통카드는 ID-1의 53.98×85.60mm 비율([ISO의 공개 규격 설명](https://www.iso.org/fr/standard/31432.html)), 종이 절취표는 앱 디자인 기준 140×65 비율이다. 종이표 치수는 코레일 공식 규격으로 확인한 값이 아니다. 기본 캔버스는 각각 269.9×428px와 700×325px로 동일한 5px/mm 배율이며, 선택 영역의 실제 너비와 높이에 맞춰 축소/확대한다. 모바일 선택 화면의 카드는 높이 200px에 맞춰 표시한다. 화면의 물리적인 mm 크기는 모니터 보정 없이 보장하지 않는다.
- 선택한 여정은 발급 시 스냅샷으로 고정한다. 새 승차권은 여정을 진행하지 않을 때 다시 고를 수 있다. 진행 중에는 현재 승차권을 읽기 전용으로 보여준다.
- 재발급 시 기존 객실 프레임을 다시 로드하지 않고 캐릭터 색상을 변경하고 좌석 선택을 초기화한다.
- 모션 감소 설정에서는 대기와 애니메이션을 줄인다. 모바일은 승차권 영역 안에서 세로 스크롤하며 데스크톱 1366×650/1440×900에서는 첫 화면이 창 높이에 들어간다.

## 검증

`npm test` 59개와 `npm run check`. 전용 테스트 Chrome에서 `node scripts/boarding-check.mjs`, `node scripts/boarding-touch-check.mjs` 실행 (`JF_QA_PORT` 기본 9224).

브라우저 검사: 마우스 직선 자르기, 카드 밖에 놓기/끌어 태그하기, 음성·효과음·진동 API 요청, 2시간 민트/1시간 앰버의 실제 반영, 프레임 재로드 없는 재발급, 진행 중 승차권 읽기 전용, 창 크기별 배치, 이탈 확인창 수락·취소 및 취소 후 이동. 터치 검사에는 양방향 자르기, 중간/선 밖/취소 동작 거부와 소리 끄기를 포함한다. API 요청 검사는 실제 스피커 음질이나 진동 모터 확인을 뜻하지 않는다. 캡처/결과는 루트 `tmp/boarding-qa/`, `tmp/boarding-touch-qa/`에 저장한다.

## 이전 새로고침 진단 정정

기존 `beforeunload` 가드는 실행/일시정지 중인 여정을 떠날지 묻는다. 이전 CDP 테스트가 이 확인창을 처리하지 않아 `Runtime.evaluate` 타임아웃을 새로고침 정지로 오인했다. 테스트 도구에서 수락/취소를 명시하고 두 경로를 검증했다. 취소한 이탈에서 객실을 정지시키지 않도록 `beforeunload`의 조기 중단은 제거하고 실제 `pagehide` 때만 애니메이션을 멈춘다. SDK 종료 핸들러 우회 코드는 사용하지 않는다.

추가 검사에서는 VWorld SDK의 지연 콜백이 폐기된 뷰어의 `scene`을 읽는 오류도 관찰했다 (`WSViewerStartup.js`의 20초 복원 콜백). 확인창 취소 후에도 페이지가 살아 있고 현재 지도 장면이 폐기된 경우 지도 프레임만 다시 불러오는 복구 검사를 추가했다. 여정 시계와 캐릭터 상태는 유지하며 실제 이탈에서는 복구 타이머를 취소한다. SDK 내부 함수를 교체하거나 오류를 숨기지 않는다. 최종 마우스/이탈 확인 검사는 런타임 오류 없이 통과했으며 SDK 내부 지연 콜백 자체를 수정한 것은 아니다.

친구 접속, 좌석 서버 점유, 책 읽기 동작은 별도 단계다.
