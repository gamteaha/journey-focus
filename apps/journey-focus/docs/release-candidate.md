# Journey Focus · 로컬 완성도 개선 결과

2026-11-03 KST. 기존 프로젝트에서 실행 가능한 로컬 프리뷰를 다듬었다. 원본 산 영상 자체를 실사 3D로 교체한 결과는 아니다.

## 돌아와서 먼저 보기

1. 실행 중인 **http://localhost:5173** 에서 **Ctrl+F5**.
2. **백양리 → 강촌**, 화면 품질 **자동**을 선택한다. 여정·화질 설정은 브라우저에 저장된다.
3. **풍경 미리보기 → 30초 이동**. 이전보다 풍성한 풀, 초록 잎 식물, 서로 다른 나무와 지붕이 보이는 집을 확인한다.
4. Space로 일시정지/재개한다. 지도 안을 클릭한 뒤에도 동작한다. **집중 화면**은 Escape 또는 화면의 버튼으로 나온다.
5. **실제 장면과 비교**에서 기존 사진·영상·지점 저장을 사용할 수 있다. 두 화면의 위치는 수동 정렬이며 자동 동기화가 아니다.

서버가 꺼졌다면 앱 폴더에서 `node server.mjs` 또는 기존 `start.cmd`를 실행한다. 새 API 키는 필요 없다. 기존 `.env.local`을 사용한다.

## 달라진 것

- 화면 여백·정보 순서·타이머·로딩·모바일·집중 화면을 정리했다. 360/390/768/1440px에서 가로 넘침과 집중 화면 종료 버튼을 검사했다. 키보드 포커스, 건너뛰기 링크, 동작 줄이기 설정을 보강했다.
- **자동 / 균형 / 높은 디테일 / 가볍게**로 화질을 통합했다. 실제 SDK에 적용되는 렌더 배율·지형 오차·타일 예산을 확인했다. 자동은 지속적인 성능 저하 때만 낮추며 높은 디테일을 임의로 켜지 않는다.
- SDK가 늦게 실행하는 초기 항공 비행을 처리해, 준비된 창가 시점이 다시 항공 시점으로 바뀌지 않게 했다. 이후 사용자 지도 조작은 방해하지 않는다.
- 근경 지형 보정을 프레임별로 분산하고, 변하지 않은 주택 행렬을 다시 쓰지 않는다. 카메라는 5지점을 5Hz로 조회한 뒤 매 프레임 높이를 보간한다.
- 경로의 실제 좌표를 바꾸지 않고 방향을 국소적으로 연결해, 굽은 지점의 시선 전환을 완화했다. 중복 좌표 때문에 카메라 위치가 NaN이 되는 경우도 막았다.
- 풀 72군락은 군락당 256개의 휘어진 잎으로 밀도를 높였다. 작은 잎 식물은 실제 CC0 재질의 3개 식물을 묶어 18군락으로 배치했다.
- 소나무와 활엽수형 모델을 각각 5개씩 섞었다. 서로 다른 원본 크기에 맞춰 약 8~10m로 조절했다. 경량 메시·원본 재질을 사용하며 전체 근경 메시 예산은 약 62만 삼각형이다. 실제 지역 수종을 검증한 배치는 아니다.
- 주택은 평탄한 후보지를 고르고 바닥을 기초로 연결한다. 큰 옹벽이 필요한 급경사 자리는 생략한다. 마지막 실제 지도 검사에서는 3채를 표시했고 기초 높이는 약 0.49/0.90/1.46m였다. 지붕과 두 면이 드러나도록 방향을 다양화했으며, 배치 경로는 선로 방향과 별도로 유지한다.
- 완료된 학습 세션이 도착점 위치를 계속 전송해 비교·풍경 카메라를 빼앗던 문제를 고쳤다. 모델 로딩에는 20초 제한과 취소·정리·다시 불러오기를 넣었다. 렌더 오류가 나면 초기화가 나중에 성공 상태로 덮어쓰지 못하게 했다.
- 풍경 미리보기에도 선택한 합성 열차 소리가 연결되며, 자체 재생 시간에 맞춰 종료된다. 역·시간·시점·화질은 저장하지만 소리나 세션을 자동 재생하지 않는다.

## 렌더링과 이동 측정

CPU 계측에서 타일 완료 때 약 153지점을 동기적으로 다시 조회하는 일이 긴 정지의 주요 원인이었다. 같은 구간의 단계별 관측에서 최대 프레임 간격은 약 408ms에서 43ms로 줄었고, 최종 관측의 95백분위는 약 29ms였다. 이는 단일 환경의 단계별 프로필이며, 기기·타일 캐시·후속 장면 구성에 따라 달라진다. 모든 끊김을 없앴다는 뜻은 아니다. [집계와 해석](performance-findings.md).

최종 혼합 식생/구도에서 실행한 독립 높이 검사는 1,477프레임을 관측했고 최대 프레임 간 높이 변화는 약 0.040m였다. 지형 캐시 조회 한 프레임이 이상하게 나온 지점은 별도 provider 조회로 다시 확인했고 카메라는 지면 위 약 6.31m였다. 후속 조회가 해당 순간의 렌더 메시와 완전히 같음을 보장하지는 않는다. [최종 이동 집계](motion-overnight.json).

소나무는 한 개당 약 14.3만에서 3.6만 삼각형으로 줄이고, 같은 카메라에서 원본과 경량 메시를 대조했다. 더 풍성한 활엽수형 모델도 원본 206만 삼각형에서 약 5.9만으로 경량화해 실제 SDK의 재질·크기를 확인했다. 원본 이미지는 변경하지 않았다. 제작 원본/도구는 별도의 무시되는 `BAI/tmp`에 두며 실행 앱은 새 npm 의존성을 필요로 하지 않는다.

산의 영상 품질을 실제로 바꾸려면 더 나은 지역 데이터나 정렬된 촬영 자료가 필요하다. **일반 이미지 생성 API를 붙이는 것만으로 정확한 실사 3D가 되지는 않는다.** 현재 적용한 렌더링 예산, 실사 비교 제작 순서, 외부 3D 타일·직접 촬영 재구성의 조건은 [렌더링 계획](rendering-roadmap.md)에 정리했다. 새 유료 서비스·계정·API 키·공개 배포는 추가하지 않았다.

## 남은 범위

원본 산의 위성 영상/지형 해상도, 실제 선로 표고, 터널 내부, 실제 현장 건물과 수종을 완성한 상태는 아니다. 기본 5.3km 선형에는 터널로 표기된 구간이 포함되며 지형 위에서 조망한다. 300m 근경의 집·식생은 재구성이다. 다른 역 조합은 역 사이 보간 경로이다.

이전 비교 지점의 `quality` 데이터는 호환성을 위해 보관하지만, 실제 화질은 상단 품질 메뉴가 한 곳에서 제어한다. 저장된 비교 지점은 카메라와 건물 레이어를 복원한다.
