# 열차 도착 로딩 화면

카드 태그/절취선 자르기 확인 뒤 ‘열차가 들어오는 중이에요’ 화면을 표시한다. 객실과 초기 창밖 지형이 준비되면 자동으로 입장한다. 이 화면을 그린 다음 무거운 초기화를 시작한다.

## 준비 조건과 진행률

- 객실 FBX 다운로드 진행 이벤트를 받아 표시한다. 재질 지정 후 Three.js `compileAsync()`로 셰이더를 준비하고 실제 첫 3프레임을 그린 뒤 `jf:cabin-ready`를 보낸다.
- 객실이 준비된 후 객실 렌더 루프를 잠시 멈추고 지도 SDK를 초기화한다. 두 3D 엔진의 초기 GPU 작업을 한꺼번에 시작하지 않는다.
- 기존 지도 `map-ready` 신호 뒤 현재 승차권의 출발 위치를 요청 ID와 함께 보낸다. 그 위치에서 지도 3프레임 이상 렌더링 + `globe.tilesLoaded`를 만족한 확인 응답을 기다린다. 캐시를 재사용해 반대 방향으로 떠날 때도 이전 위치의 준비 완료 신호를 사용하지 않는다. 지도와 객실이 모두 준비된 뒤 객실 루프를 다시 켜고 화면을 전환한다.
- 진행률은 준비 단계별 가중치다. 모델 준비는 10~65%, 지도/초기 지형 준비는 65~98%, 입장 조건을 모두 충족하면 100%다. 다운로드 총량을 알 수 없는 구간은 완료를 추정하지 않고 해당 단계에서 기다린다. 타이머로 100%를 만들지 않는다.
- 지도의 준비 조건은 초기 카메라 위치의 지형이다. 모든 경로의 건물·텍스처를 미리 내려받거나, VWorld가 제공하지 않는 상세 로딩 상태까지 보증하지 않는다. 이동 중 새로 보이는 영역은 계속 스트리밍된다.

## 실패·취소·재사용

객실 준비 60초, 지도 초기화 최대 65초, 초기 지형 표본 최대 35초의 단계별 제한을 둔다. 해당 단계가 실패하거나 지연되면 로딩 화면에 재시도와 승차권으로 돌아가기 버튼을 표시한다. 완료되지 않은 상태에서 객실을 자동 노출하지 않는다.

준비된 객실은 재시도/다음 승차권에서 재사용한다. 실패하거나 응답하지 않는 객실은 새 프레임으로 재시도한다. 지도 재시도는 필요한 경우 지도만 다시 불러온다. 대기를 취소하면 `AbortSignal`로 대기 작업과 진행 콜백을 정리하고 늦게 도착한 이전 시도의 완료를 무시한다.

배경 객실/지도의 실제 크기는 유지해 렌더링을 준비하되, 부모 작업 영역을 `inert`로 잠근다. 로딩 화면이 사라진 뒤에만 입력을 허용한다. 집중 타이머는 기존과 같이 자리 선택 후 출발 버튼을 눌러야 시작한다.

## 검증

전용 QA Chrome(기본 9224)에서 `node scripts/arrival-check.mjs`:

- API 응답을 실제로 보류하는 동안 65%에서 대기하며 100%/객실 노출로 넘어가지 않음.
- 객실이 렌더링 준비를 끝낸 뒤 지도 연결 요청을 시작함.
- 연결 실패 시 재시도 화면 유지, 객실 캐시 재사용, 진행 중 취소와 재입장.
- 초기 지형 준비 후 100%, 입력 잠금 해제, 타이머 미시작.
- 1366×650, 1440×900, 390×844, 844×390 배치와 준비 중 캐릭터 입력 차단.

결과/캡처는 루트 `tmp/arrival-qa/`에 저장한다. 로딩 화면은 첫 입장 준비 구간을 처리한다. 이동 중 FPS 개선이나 모든 기기의 끊김 제거를 측정/보장한 변경은 아니다.
