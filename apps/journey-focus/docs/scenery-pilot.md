# 백양리 300m 근경 보강 시안 · 2026-11-03

> 이 문서는 해당 단계의 기록입니다. 최신 검증·식생 밀도·품질 설정은 [release-candidate.md](release-candidate.md)에서 확인합니다.
## 구현

기존 실제 API 지도 위에 선택적으로 표시하는 풍경 시안을 추가했다. 실제 지형/선로와 새로 배치한 모델을 구분하기 위해 시안 활성화 중 화면에 재구성 표시를 유지한다.

| 항목 | 데이터/제작 방식 |
| --- | --- |
| 수평 경로 | 기존 OSM 백양리–강촌 선형의 150~450m, 약 300m |
| 지형 | 브이월드 SDK. 표고만 런타임 메모리에서 조회 |
| 주택 | 직접 작성한 지붕/벽/창문/문/기단 형상 + Poly Haven CC0 벽/지붕 색상·노멀 재질 |
| 식생 | Poly Haven CC0 소형 소나무/관목 glTF에서 단일 식생 선택 및 크기 보정 |
| 전봇대 | SDK 원기둥 형상 |
| 배치 | 선로 상대 거리 기준으로 생성한 **현장 미검증 재구성 배치** |
| 카메라 | 주변 지형 표고를 평활화한 경로 + 6m 기준, 진행 방향 오른쪽 90°, 수평 시선 |

주택 후보 5곳 중 적합한 자리와 소나무 10개, 관목 18개, 낮은 풀 군락 72개, 전봇대 8개를 표시한다. 주택과 겹치는 식생은 숨긴다. 시안은 30초에 300m를 이동하며 실제 열차 시각표를 뜻하지 않는다. 기존 학습 세션을 일시정지하고 별도의 시계로 재생한다. 취소/정지/오류 시 모델과 전봇대·기초를 정리하고 원래 건물 레이어 및 카메라 위치를 복원한다.

## 사용 자산

외부 자산은 Poly Haven의 CC0 자료만 사용했다. [라이선스](https://polyhaven.com/license).

- [Pine Sapling Small](https://polyhaven.com/a/pine_sapling_small)
- [Shrub 03](https://polyhaven.com/a/shrub_03)
- [Clay Roof Tiles 02](https://polyhaven.com/a/clay_roof_tiles_02)
- [Plastered Wall 02](https://polyhaven.com/a/plastered_wall_02)

원본 파일과 체크섬은 `public/assets/catalog.json`에 기록했다. 식생 glTF는 여러 개체가 나열된 원본에서 단일 개체를 선택해 원점에 놓고 미터 크기를 보정했다. 주택 형상은 이 프로젝트가 직접 제작했으며 외부 텍스처와 구분한다. 외부 자산의 CC0 표시는 직접 제작한 코드/형상의 라이선스를 새로 부여한다는 뜻이 아니다.

자산 재생성 순서:

```powershell
python scripts/prepare-scenery-assets.py
python scripts/build-scenery-house.py
python scripts/normalize-vegetation.py
```

이 과정은 Poly Haven 자산만 내려받으며 프로젝트 키를 읽지 않는다. API 식별용 User-Agent를 사용하고, 원본 다운로드 체크섬을 확인한다. 웹 서버는 catalog에 명시된 안전한 상대 경로만 정적 파일로 제공하며 바이너리를 그대로 전달한다.

## 검증

- 단위/서버 테스트 14개 통과, 문법 검사 통과
- 실제 SDK `Model.fromGltf` / `readyPromise`로 모델 105개 로딩 확인
- 실제 지형 높이 조회 후 주택과 입체 소나무 표시를 캡처로 확인
- 지형 타일의 상세도 변경 시 모델 원점을 현재 화면 지형에 다시 맞추며, 105개 모델 원점의 표고 차이를 수치 검사로 확인
- 30초 전체 이동 완주, 일시정지, 위치 탐색, 처음으로 확인
- 로딩 중 취소 후 재진입 확인
- 학습 타이머에 시안 시간이 누적되지 않음을 확인
- 종료 시 전봇대 엔티티 제거와 원본 건물 표시 상태 복원 확인
- 모바일 가로 넘침 없음
- 최종 실제 브라우저 시나리오의 페이지 오류 0개
- 독립 코드 리뷰에서 중요 결함 없음

검증 명령: `npm.cmd test`, `npm.cmd run check`, `node scripts/scenery-check.mjs`. 브라우저 검증에는 별도 QA Chrome의 CDP 포트 9223과 실행 중인 앱이 필요하다.

## 남은 한계

현재 결과는 실제 지형 위에서 재질 있는 집과 입체 식생이 표시·이동되는 기능 시안이다. 실사와 일치하는 마을, 충분히 조밀한 숲, 실제 철도/교량 높이, 현장 식생 종류, 정밀 건물 충돌, 터널 내부를 재현한 결과가 아니다. 원본 산의 지형·영상 품질은 유지되며, 추가된 근경만 입체로 보강한다. 실사 수준을 목표로 하려면 다음 단계에서 위치가 확인된 사진을 기준으로 개체의 형상·밀도·배치를 정교하게 조정해야 한다.

주택은 중심과 11×10m 대지의 모서리/변 중앙 9점을 검사한다. 선로를 침범하지 않는 주변 후보지 중 경사가 작은 곳을 고르고, 수평 바닥 아래를 흙빛 기초로 연결한다. 표고 차이가 2.5m를 넘는 곳은 주택과 기초를 숨긴다. 이는 실제 토목 설계가 아닌 시각적 보정이며 9점 사이의 작은 지형 굴곡까지 보장하지 않는다. 표시 가능한 주택 수는 불러온 지형 상세도에 따라 달라진다.

풀은 직접 제작한 휘어진 잎 64개/군락(320삼각형), 명시적 법선과 잎별 색을 사용한다. 72개 군락을 불규칙한 무리로 배치하고 주택과 겹치는 식생은 숨긴다. 카메라 경로는 최소 6m 비워 둔다. 원본 위성 영상과 산의 상세도가 낮은 점은 이 변경으로 해결되지 않는다.

사용자 이동 피드백에 따른 카메라 수정과 전후 측정은 [motion-fix.md](motion-fix.md)에 기록했다.
