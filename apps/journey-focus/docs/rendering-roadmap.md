# 사진 같은 창밖 풍경을 위한 렌더링 계획

작성/공식 문서 확인: 2026-11-03 KST. 현재 구현과 앞으로 필요한 데이터를 구분한다.

## 지금 적용한 경로

현재 VWorld 지형과 위성 영상 위에 근경을 보강하는 방식을 유지한다. 지형 제공자·좌표계·API를 교체하지 않고, 작은 풀/잎 식물과 재질 있는 집을 가까운 구간에 배치한다. 기존 산 영상의 세부 정보가 늘어난 것은 아니다.

화면 품질은 한 곳에서만 제어한다. 카메라/레이어 제어와 분리해 비교 모드의 설정이 뒤늦게 화질을 덮어쓰지 않게 했다.

| 설정 | 렌더 배율 | 지형 화면 오차 기준 | 타일 캐시 예산 |
| --- | ---: | ---: | ---: |
| 가볍게 | 0.75 | 3 | 128 |
| 균형 | 1 | 1.7 | 256 |
| 높은 디테일 | 1.25 | 1 | 384 |

위 값은 공개 SDK 속성의 존재·쓰기 가능 여부를 검사한 뒤 적용한다. 지원되지 않으면 기본값을 유지하며 화면에 적용 제한을 알린다. 화면 오차 기준은 낮을수록 세부 지형을 더 요청하지만 원본에 없는 정보를 복구하지는 않는다. 높은 디테일은 사용자가 직접 선택하며 자동으로 켜지지 않는다.

자동은 기본적으로 균형을 사용하고, 제한된 기기에서는 가볍게 시작한다. 2초 측정 창 네 번 연속 24FPS 미만이면 낮추며, 회복 대기와 충분한 연속 여유 프레임/타일 로딩 조건을 거쳐 균형으로 돌아온다. 화질 선택을 바꾸는 동작은 카메라 위치를 변경하지 않는다. 실제 지원 속성과 값은 브라우저 검사에서 확인했다.

근경 예산은 풀 72개 군락(군락당 256개 잎, 총 92,160삼각형), 초록 잎 식물 18개 군락(공유 메시로 3개 식물/군락, 2,970삼각형), 경량 소나무 5개와 활엽수형 5개, 주택 후보 5곳이다. 원본 소나무 한 모델이 약 142,506삼각형이므로, 숲을 더 빽빽하게 할 때 이 모델을 무작정 복제하는 것은 피한다. 조사한 더 풍성한 원본 나무는 25~101MB였다. 101MB 활엽수 원본은 별도 tmp에 두고 원본 재질의 경량 변환본(약 5.9만 삼각형/9.2MB)을 적용했다. 소나무도 약 3.6만 삼각형으로 줄였고, 현재 전체 근경의 메시 예산은 약 62만 삼각형이다.

## 가장 효과가 큰 다음 제작 순서

1. **같은 위치의 실사 확보와 정렬.** 사용 권한이 있는 사진/영상에서 대표 장면 3곳을 고른다. 좌표·촬영 방향·시선 높이를 맞추고 능선, 집 위치, 식생 밀도를 먼저 비교한다. 현재 공유된 YouTube 영상은 임베드 참고 자료이며 지점별 위치 검증이나 원본 프레임 추출은 하지 않았다.
2. **좋은 300m 한 구간 완성.** 집이 있는 평탄지, 선로 둑, 수풀을 사진에 맞춰 다시 배치한다. 현재 기초의 9점 검사는 시각적 보정이므로 대지 전체를 덮는 촘촘한 지형 검수와 현장 지점 확인이 필요하다. 가까운 풀은 고밀도, 중간 거리는 단순 메시, 먼 숲은 가벼운 군락 또는 검증된 billboard 방식으로 나눈다. 원본 나무의 반복 횟수 대신 가시 거리와 메시 예산을 제한한다.
3. **그 다음 노선을 확장.** 단일 구간에서 시점 튐, 기초 벽, 눈에 띄는 반복 패턴, 프레임 끊김을 먼저 줄인다. 실제 레일 표고와 터널을 확보하기 전에는 지형 위 조망을 실제 기관사/차창 높이로 표시하지 않는다.

이 순서는 이번 구현을 바탕으로 한 제작 판단이다. 아직 현장 사진을 지리적으로 정렬하거나 확장 노선을 제작한 결과는 아니다.

## 실사 수준으로 바꾸려면

| 대안 | 얻을 수 있는 것 | 진행 전 확인할 것 | 이번 구현 여부 |
| --- | --- | --- | --- |
| 현재 지도 + 근경 제작 | 기존 API를 유지하며 가까운 물체의 입체감 개선 | 실제 사진 정렬, 모델 예산, 지형 접점 | 구현 |
| 별도 photorealistic 3D tile 제공자 | 사진 재질이 입혀진 지역 단위 3D 메시 | 해당 철도 구간 커버리지, 지상 시점 품질, 비용, SDK 호환 | 조사만 |
| 직접 촬영한 구간의 photogrammetry / Gaussian Splatting | 촬영된 실제 장면의 외관 기반 재구성 | 여러 시점의 원본 촬영 자료, 카메라 정렬, 학습/변환 환경, 브라우저용 경량화 | 미구현 |
| 일반 이미지 생성 API | 새로운 분위기/텍스처 시안 | 실제 위치의 일관성·정확성을 별도로 검증 | 사용하지 않음 |

Google의 Photorealistic 3D Tiles는 고해상도 사진 재질을 가진 3D 메시를 제공하며, 사용하려면 결제 계정·API 활성화·키가 필요하다. **백양리–강촌 구간의 제공 여부와 지상 시점 품질은 확인하지 않았다.** 지금 키를 새로 발급받으면 이 구간이 자동으로 사진처럼 된다고 보장할 수 없다. 현재 VWorld 엔진에 그대로 끼워 넣는 호환성도 검증하지 않았다. [공식 3D Tiles 안내](https://developers.google.com/maps/documentation/tile/3d-tiles), [사용량/과금](https://developers.google.com/maps/documentation/tile/usage-and-billing).

외부 타일로 전환할 경우 제공자 표기와 허용된 이용 방식도 별도로 맞춰야 한다. 저장·추출을 전제로 현재 근경 제작용 원본처럼 취급하지 않는다. [Map Tiles API 정책](https://developers.google.com/maps/documentation/tile/policies).

Gaussian Splatting은 여러 사진/영상으로 포착한 장면을 다른 시점에서 렌더링하는 재구성 방식의 후보이다. 원 논문 결과를 현재 브라우저·기기·철도 구간의 성능 보장으로 해석하지 않는다. 영상 URL 하나나 이미지 생성 API만 연결해 현재 지형 전체를 정확한 실사 장면으로 바꾸는 기능을 구현한 것은 아니다. [연구진의 원 논문/코드 안내](https://repo-sam.inria.fr/fungraph/3d-gaussian-splatting/).

따라서 다음 투자는 AI API보다 **정렬 가능한 실제 사진·좋은 구간 데이터·성능 예산에 맞는 근경 제작**을 먼저 권장한다. 새 결제/계정/키가 필요한 대안은 사용자 확인 뒤 별도 시험한다.
