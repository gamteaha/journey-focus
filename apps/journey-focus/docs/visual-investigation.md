# 실사 대조 기반 풍경 개선 · 2026-11-03

## 이번 실행 결과

실사와 지도 화면의 차이를 판별할 수 있는 비교 모드와 렌더링 설정을 구현했다. 기본 건물을 LoD4에서 전체 상세도(All)로 변경했고, 카메라의 기본 높이/방향을 개선했다. 실제 영상과 지리적 위치를 완전히 정렬한 상태나 숲/주택의 사실적 재현을 완료한 상태는 아니다.

참고 영상: [경춘선 춘천행 361x05편성 상봉~춘천 주행 2026.09.25 금요일](https://www.youtube.com/watch?v=s9KmHA-Jty4). 공개 제목/썸네일 및 공식 임베드 플레이어 연결을 확인했다. 영상 전체의 역별 타임스탬프를 검증하지 않았으므로 임의의 백양리 시각은 입력하지 않았다.

## 같은 카메라로 건물 레이어 비교

- 위치: 경도 127.5891698, 위도 37.8307979 (백양리역 인근 OSM 선형의 출발 노드)
- 해발 높이: 약 85.69m, 지형 상대 약 30m
- 경사 -4°, 화각 65°, 진행 방향 기준 왼쪽 90°
- 두 캡처 모두 위 설정과 좌표를 유지했다. 필터·AI 변환·외부 자산 합성 없음.

| 레이어 | 실제 표시 | 선택된 SDK 객체 | 선택된 타일 |
| --- | --- | ---: | ---: |
| 기존 LoD4 | 활성 | 0 | 0 |
| 전체 상세도(All) | 활성 | 251 | 16 |

객체 수는 조사 시점의 비공개 SDK 내부 진단 통계이다. 사용자 기능은 이 내부 속성에 의존하지 않으며, 이 수치를 건물 총수나 지역 커버리지 비율로 해석하지 않는다. 구조화한 실제 결과는 [layer-investigation.json](layer-investigation.json)에 기록했다.

캡처: [기존 LoD4](../../../tmp/journey-focus-layer-lod4.png), [전체 상세도](../../../tmp/journey-focus-layer-all.png).

관찰: All 레이어에서는 강 건너 건물들이 입체로 나타났다. 그러나 여러 건물이 단순한 밝은색 모형이어서 실제 벽/붉은 지붕의 세부 재질까지 복원된 것은 아니다. 산의 숲도 독립된 나무가 아니라 주로 지형 위 영상으로 보인다. 따라서 건물 레이어 교체는 일부 평면 문제의 개선이며 실사 수준 완성을 뜻하지 않는다.

## 구현한 비교 절차

1. 비교 모드에서 먼저 동일 장소를 찾는다. 초기 영상 시각 0:00은 백양리 위치와 일치한다고 표시하지 않는다.
2. 영상 프레임 또는 로컬 사진과 지도 화면을 나란히 놓고 시선 방향/높이/경사/화각을 맞춘다.
3. 능선 윤곽, 건물 실루엣, 나무의 입체감, 가까운 물체의 이동을 각각 살핀다.
4. LoD4/All/LoD1~3, 지형 표준/정밀을 비교한다. 단순히 렌더링 정밀도를 높여도 미제공 나무·텍스처가 생기지는 않는다.
5. 비교 지점을 메모와 함께 저장한다. 저장값은 항상 manual-unverified이며 사진 원본이나 API 키가 포함되지 않는다.

## 다음 제작 구간과 완료 기준

OSM 선형에서 첫 번째 연속 지상 후보는 약 1.16km이다. 우선 이 중 짧은 구간을 사용한다. 이 구간을 실제 주행 영상과 대조한 타임스탬프가 확보되면 아래 순서로 진행한다.

| 단계 | 구체적 작업 | 완료 기준 |
| --- | --- | --- |
| 위치 정렬 | 역/교량/도로 등 구별 가능한 지표를 영상에서 확인해 비교 지점 3개 기록 | 시간대와 지도 위치의 근거가 메모에 존재 |
| 카메라 정렬 | 같은 방향·높이·화각으로 전후 화면 캡처 | 능선/수평선 위치 차이를 비교할 수 있음 |
| 근경 제작 | 사용할 수 있는 별도 지형/건물/식생 자산으로 가까운 집·나무·전봇대를 보강 | 실제 사진과 대조한 형상·배치 근거가 있음 |
| 이동 검증 | 창가 카메라로 같은 짧은 구간 반복 이동 | 위치 튐, 지형 통과, 그림자·표면 깜빡임을 확인하고 수정 |
| 성능 결정 | 이전 버전과 개선 버전의 같은 이동 조건 비교 | FPS/프레임 시간·로딩량을 기록하고 품질 수준 결정 |

근경 제작이나 사진 기반 3D 복원은 이번 버전에 수행하지 않았다. 브이월드 화면을 추출·재가공하거나 제3자 영상을 AI 입력으로 보내지 않았다. AI API 결제도 필요하지 않았다.

## 기술적 주의

- 실제 SDK는 레이어 `visible`이 읽기 전용이다. `viewer.map.getElementById(id).show()/hide()`를 실제 브라우저에서 확인해 사용한다.
- 지형 정밀도는 `globe.maximumScreenSpaceError`를 표준 2, 정밀 1로 조절한다. 원본 높이 데이터의 한계를 넘는 새 형상을 만들지 않는다.
- 낮은 높이에서 새 타일이 로딩되면 지형 표고가 달라질 수 있어, 잠긴 비교 카메라는 타일 로딩 완료 시 상대 높이를 다시 적용한다. 실제 철도/교량 표고는 아니다.
- YouTube는 공식 IFrame API로 표시한다. 사진은 브라우저에서만 열고, 비교 저장/내보내기에는 포함하지 않는다.

## 검증

단위/서버 테스트 12개가 통과했고 문법 검사도 통과했다. 실제 Chrome에서 아래 항목을 확인했으며 최종 브라우저 검사에서 페이지 오류는 0개였다. 독립 코드 리뷰에서 지적된 카메라 잠금 복원과 영상 재시도 문제를 수정한 뒤 재검증했다.

- 카메라 범위와 영상 시각 파싱, 비교 기록의 경로 식별/비밀 제외
- 실제 SDK의 All/LoD4 전환, 지형 정밀도, 카메라 화각과 실제 지형 상대 높이
- 비교 모드 진입 시 세션 일시정지 및 종료 시 자동 재개하지 않음
- 지도 재연결/비교 중 세션 종료 후에도 비교 카메라 잠금 유지
- 로컬 사진 표시, 비교 지점 저장/복원, 잘못된 경로 거부, 모바일 가로 넘침 없음
- YouTube 플레이어 표시 및 실패 후 재시도

YouTube 준비 상태 도달과 최소 200×200 이상의 실제 플레이어 표시를 확인했다. 오류 재시도 시험은 실제 플레이어의 준비 알림만 테스트 환경에서 누락시켜 초기화 시간 초과를 재현하고, 플레이어 제거/다시 생성/준비 완료까지 확인했다. 영상 전체의 재생 내용이나 위치별 타임스탬프를 분석한 검증과는 구분한다.

재현 명령: `npm.cmd test`, `npm.cmd run check`, `node scripts/comparison-check.mjs`, `node scripts/comparison-errors-check.mjs`. 레이어 조사 재현: `node scripts/inspect-layers.mjs`. 브라우저 검사에는 별도 QA Chrome(CDP 포트 9223)과 실행 중인 로컬 서버가 필요하다.
